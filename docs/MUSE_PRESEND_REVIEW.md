# Muse 事前双重验证协议 v1（2026-10-12）

状态：影子试运行。用户已授权实施；不调评分/门槛/仓位、不把通过标识当买入授权。无模型调用、无新增收费服务。

## 稳定读取与写入位置

- 草案：私有 `bluestevenr-lang/v88-daily-report`，`review-exchange` 分支。
- 按日入口：`drafts/YYYY-MM-DD/manifest.json`。日期为北京时间。
- manifest 的 `files` 保留所有草案修订；每个 delivery_id 的当前版本见 `drafts/<日期>/<sha256(delivery_id)>/latest.json`，读取其 `file`。
- 草案保留 `text` 和 `payload_parts`（生成时正文；未附加发送层时间行/分段编号）。正文不包含 Muse 裁决。
- 草案的 `verdict_repository` 与 `verdict_file` 给出直接提交位置，无需自行猜路径。
- 裁决只写：私有 `bluestevenr-lang/v88-muse-verdicts` 的 `main` 分支，`verdicts/<日期>/<sha256(delivery_id)>.json`。每次独立提交，Git 历史不删除。
- 发送原文和采用裁决：原核心仓库 `feishu-delivery-state` 分支 `feishu_sync_delivery.json`。只以 `complete=true AND accepted=true` 为已投递。`muse_review` 是新增字段，不改变旧回执字段语义。`payload_parts` 仍保存实际发送的正文分段；发送层时间行/编号另加，不宣称完整群消息逐字一致。

## Muse 接入步骤

1. 原核心仓库维持 Contents 只读。
2. 为 Muse 配置仅选择 `v88-muse-verdicts` 的 Contents 读写凭据，不给核心仓库写权限。两者使用独立凭据；不要把令牌贴在对话、裁决或证据 URL 内。
3. 按 manifest/最新指针读取草案，仅核查 `items`（实际展示的 3A/Astra），不得扩大到 1A/2A 或其他市场。
4. 复制以下字段生成裁决，理由最多40字符且单行。未知、证据不足、来不及均用 unverified，不编造审核。
5. 提交后查看交换分支下的 accepted 指针及 receipt。以接收端 `received_at` 为是否赶上截止的依据。

核心仓库由现有 GitHub 云端凭据操作。Muse 不能直接写接收端 receipt、accepted、drafts 或原投递状态。独立分支不等于路径级权限；真正隔离依靠独立裁决仓库。

**截止按我方首次读取到该裁决的真实时间，而不是用户可改的Git提交时间或自填 checked_at。建议 Muse 至少提前10分钟提交并确认 receipt。** 当前没有承诺截止前一秒提交也能采用。未被及时收集的版本不追认；晚到内容仍留在裁决仓库供事后分析。

草案按完整正文/事实生成 `draft_sha256`；`review_sha256` 只忽略报告标题编制钟及“摘要编制”行的变化，不忽略筛选时间、报价、价格区间、分数、风险、状态或市场。发送前重读系统数据，实质内容变化则旧裁决作废，照常发最新报告并标未验证。重复收集同一事实不重建草案；每次新版本原文件永久保留。

发送时只读取核心交换分支已验证的接收记录，最多等待15秒；错误/超时/缺少裁决均发原系统报告＋未验证。网络请求不持有投递状态写锁以外的长期等待；不为Muse启动新的价格抓取或LLM。

同一delivery_id的网络重试始终使用已冻结的最终payload_parts和裁决元数据。新ID的补发不得沿用旧裁决；非debug补发新增 supersedes 指向原时段ID。只有补发成功回执才在统计中替代旧版，旧记录不删。debug-版本独立，不计正式效果样本。

## 冻结核查口径 muse-shadow-v1

- 检查财务来源、扣非/经常性利润、一次性项目和周期性解释；证据不足不推断为通过。
- 区分当前首段结构空间、当前净RR与原计划情景收益；不把触及目标当真实盈利。
- 当前条件满足的条目：核对报价时点、入场带、风险、目标和现有系统条件，不另行放宽门槛。
- 重点观察条目：pass只认可高价值研究/等待资格；明确尚未满足的条件，不表示立即买入。
- 同源数据不是两份独立证据；给出可核查 evidence_ref。禁止以“通过Muse”为目的反向调整系统权重。
- 裁决不修改系统榜单、评分、止损、目标、期限。即使 fail，试运行只公开分歧与理由。
- 标准改变必须新版本；消费者只接受当前固定版本，不能由裁决文件自行切换。

## 统计及转正

`src/muse_shadow_stats.py --state <实际回执文件> --out <统计文件>` 只读统计完整已接受投递；排除debug与成功替代的旧版。相同模块/市场/股票/原计划锚点仅算一个独立样本；缺锚点不凑30个样本。日常重复出现不增加独立样本数。输出还包含缺锚点数与未验证覆盖。

至少3周且30个独立已裁决计划只是工程样本门槛，不代表收益验收。Astra按原15交易日窗口，3A按月跟踪与原期限结算；未触发/入场后/仅触目标分开；同日双触不明记不确定。只在有完整入场及行情轨迹后比较原系统与Muse筛选的同一批计划，含费用/跳空等原执行规则，报告净R、回撤、错失机会和区间不确定性。

草案任务同时把只读统计发布到核心交换分支 `statistics/YYYY-MM-DD.json`；没有成熟轨迹时不会输出虚构命中率。

本版不编造配对收益、不自动调权、不自动转正。统计中的 `performance_acceptance=not_evaluated_requires_matured_paired_outcomes` 明确表示效果待验证。后续由用户根据成熟样本拍板。

## 回退与诊断

发送工作流的 `V88_MUSE_SHADOW=1` 控制影子标注；设为0仅停止标注/读取，不删除任何草案/裁决/回执，不影响原报告生成与去重。草案工作流不持有飞书Webhook，不允许发消息。错误只输出异常类型及摘要计数，私有正文不上传公共仓库artifact。

## 2026-10-12 用户定版：M 网页标识与飞书共用口径

本节为用户与 Muse 最后确认的 muse-shadow-v1 完整清单。没有修改系统分数、排名、评级、价格或执行门槛；实际复核由 Muse 产出，页面不自行推算 pass/fail。

1. 财务回公告/财报原文核对，数据商与原文不符时注明。
2. 检查扣非/经常性利润和一次性项目，港美股采用经常性口径。
3. 多年经常性利润与现金流结合看周期位置；周期股必查经营现金流与净利润背离。
4. 复算当前首段净空间、净盈亏比，与原计划情景收益分开；触目标价不算真实盈利。
5. 识别错误“可买”标签：净空间至少5%，净盈亏比至少2；研究资格和买入状态分开。
6. 核对条件满足条目的报价时点、入场带、止损、目标，不放宽条件。
7. 立案未结、处罚未落地、ST未摘帽、重大问询未回等治理未出清，可否决观察通过。
8. 同源数据不算两份证据；每条有可追溯 evidence_ref，证据不足为未验证。
9. 与持仓重复暴露单列提醒，不扣公司分，不影响徽章。
10. 标准冻结、公开版本化；变更须双方确认新版本，系统不得反向调参迎合验证。

### 数据与显示

- 仅三态：`✅ Muse 认证·通过` / `❌ 不通过` / `⚪ 未验证`，统一标“（试运行）”。M 为小号文字徽章，不增加整列或大型卡片。
- pass 必须区分“认可买入条件”和“认可重点观察（不代表可买）”。显示一行理由、北京时间核查时间、criteria_version、裁决版本短码；展开看 evidence_ref、完整裁决版本以及 delivery_id/draft_sha256/item_sha256。
- `muse_review` 原字段已有 accepted_items（reason/checked_at/evidence_ref/verdict）、items（事实与 item_sha256）、criteria_version、draft_sha256、verdict_blob_sha。新增 delivery_id、slot、date、created_at、cutoff_at、scheduled_at、review_sha256、source_generated_at、display_version，旧字段语义不变。
- 后台 `muse_web_sync.py` 只用已登录 GitHub 的只读 API 读私有投递状态和私有裁决快照，不读 Webhook、不触发推送、不调用模型，不向公开仓库发布裁决/持仓或回执正文。该脚本与行情同步并行，不在渲染线程联网。
- 页面读私有本地 `data/muse_review_web.json`，按mtime缓存。每次后台同步预算25秒；当前徽章回执缓存超过5分钟、同步失败/不完整、当前条目事实或状态变化、草案改版均为未验证。保持现价、币种、真实行情时间。没有真实裁决不能产生绿色 M。
- 最终已投递回执优先于裁决仓库快照。未发送的草案裁决只出现在“仓库快照”核对区，不提前授予网页认证。
- 三时段汇总、逐份明细、原定/实际发送/筛选/行情/裁决接收/截止时间分别显示。debug 独立，成功 supersedes 替代旧版本的汇总；旧版仍可展开。历史没有 supersedes 或截止字段时显示未记录，不推断关系/时效。
- 每次读取将成功回执按内容哈希留在私有 `data/muse_receipt_archive/`，同版本不覆写；远端遗漏时保留原记录。历史页和日报从原冻结回执展示，不以当前行情回改。早期无 delivery_id 的记录只用 `legacy-receipt:<原账本键>` 作本地索引，原回执不改写。
- 当前 3A 列表、个股深度、Astra卡片显示徽章；“Muse双重验证”区块在3A总览、Astra独立页、日报与历史日历可见。

### 飞书定版文案差异

| 原试运行文案/行为 | 定版 |
|---|---|
| ✅ 认可系统当前条件 | ✅ 认可买入条件 |
| ✅ 认可重点观察（非买入） | 尾行固定 `✅ 认可重点观察｜理由`，汇总明确不代表买入 |
| ❌ 未通过 | `❌ 不认可｜理由` |
| 未验证可能带内部原因 | 固定 `⚪ 未验证`，内部原因留回执 |
| 条目不显示标准/核查时间/裁决版本 | 在认证尾行之前增加一行标准、核查时间、裁决版本短码；完整版本留回执 |
| 汇总仅说明观察非买入 | 加“仅针对本版草案，不代表收益保证；认证≠买入授权” |
| 可在绑定相同语义后重绘编制时间 | 直接复用已审草案完整正文和时间，不重绘标题/编制时间 |

合并后冻结正文及元数据，失败重试沿用冻结结果。此部署不补发旧时段、不自动给旧消息添加认证；下一正常新投递使用定版文案。
