制定时间：2026-08-29，北京时间。用户要求：Win 7×24 常驻；Mac 开机后能够远程查看和修复 Win；飞书能看到故障与进度；只用既有订阅，不增加按量模型费用。

## 1. 主机分工与安全接入

Win 承载正式机器人。Mac 是远程诊断与操作入口，不要求用户每次在两台机器之间转述报错。Mac 临时机器人与 Win 正式机器人必须按不同应用身份明确区分；同一应用不能自动双机抢接收。

首选 Codex/ChatGPT 桌面应用的正式 Remote 连接：在重装后的 Win 上启用“允许其他设备连接”，与 Mac/手机重新确认同一账号和工作区并完成设备配对。配对是一次性的必要步骤，不能用一份 GitHub 文件替代。连接成功后，Mac 可读取 Win 任务状态、继续现有任务、检查日志并执行用户授权范围内的修复。

不开放公网 RDP、SSH 或 OpenClaw 管理端口，不生成远程任意命令执行接口，不把 GitHub 当自动执行命令的邮箱。若以后使用 SSH 备用通道，必须先有可信私网/安全隧道、密钥认证、固定主机身份校验；不能猜测地址或关闭 host-key 校验。

官方依据：[Remote connections](https://learn.chatgpt.com/docs/remote-connections)。远程可达还取决于主机联网、桌面应用运行、登录与配对状态；仅有电源常开并不够。

## 2. 五层状态分别验收

| 层 | 检查内容 | 不能混淆的情况 |
| --- | --- | --- |
| 远程主机 | Mac 能否连接正确的 Win 主机/任务 | 未配对、远控关闭不等于 Win 断电 |
| 网关 | OpenClaw 网关请求是否成功 | 进程还在不等于它能处理请求 |
| 飞书通道 | 正确账户 enabled / configured / running / connected，探针正常 | `probe.ok` 不单独证明长连接存在 |
| GPT 回答 | 原订阅、指定模型的真实哨兵问答 | OAuth元数据或 `/new` 不是模型实测；过期标签也不等于刷新一定失败 |
| V88 业务 | 新鲜数据、同事实包、GPT/K3/书理、中央裁决与隐私测试 | 业务待审不能让基础聊天和故障通知一起消失 |

健康程序只输出固定字段和错误分类。未知状态写“未验证”，绝不自动当作通过。没有真实模型探针结果时，端到端状态保持未验证。

## 3. 监控和通知

- Win 本机健康任务：计划每5分钟检查一次，登录时启动，输出到用户本机 `.openclaw/ops`。不修改原 Gateway 任务。
- 该监控任务使用当前用户身份以保持凭据范围一致；现有安装材料使用交互登录任务，**不能宣称未登录/系统重启停在登录界面时监控也一定运行**。这一条件必须现场验收并记录。
- 默认不调用 GPT/K3、不读持仓、不读私人记忆、不上传完整日志。它是连接诊断，不是投资评审。
- 只有显式启用通知，且该飞书账户有唯一既有配对用户时，才发脱敏运维消息。重复故障去重；通知发送失败不冒充已送达。
- 告警包含故障层、检测时间、是否已验证和建议动作；不包含账号标识、token、密钥、资产金额或持仓数量。
- Mac 当前任务增加每小时的远端状态检查。没有远程主机时记录“未接入”；相同故障不反复向飞书刷屏。
- Mac 关机/休眠时，其本地定期检查不会运行。Win 自身断网/断电时也无法自行发送告警；在没有另一台在线观察者的情况下，不能承诺全天候即时断电通知。

## 4. 修复权限边界

监控默认只读，不能自动启用被明确关闭的渠道、重新登录、替换模型、扩大工具权限或更改交易纪律。也不自动反复重启故障程序。

Mac 远程接入后，运维先查看脱敏健康报告，再查必要日志。确认原因后可在用户既有授权范围内做有回退的修复；遇到需要用户亲自完成的 OAuth/设备配对必须明确报告。禁止把“等待授权”写成“正在运行”。

任何运维变化不写 `kimi_verify.json`，不改变 GPT/K3/书理的投票权重和投资闸门，不交易。核心系统升级继续遵守双席互审。

## 5. 新的恢复顺序

1. 先恢复正式远程连接，记录正确主机与已有任务；未连接就诚实标为待接入。
2. 恢复最小安全聊天：原 GPT 订阅问答、唯一飞书绑定、只读隔离、手机自然语言问答。业务数据尚未验收时只提供普通聊天/诊断，不发布投资名单。
3. 在 Win 安装本机监控，确认脱敏状态文件更新和故障消息可以到达既有用户。
4. 验收退出 Codex 后机器人仍可回答、断线后的可恢复性、Win 重启后的服务状态。禁止用“电脑不关机”替代这些测试。
5. 最后接通完整 V88：投影/隐私测试、最新事实包、GPT+K3实审和中央裁决。审核未完时明确回复业务待审，不伪造3A，也不封死诊断聊天。
